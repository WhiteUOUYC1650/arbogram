# SLink Messenger

**SLink** — современный мессенджер на Next.js + Firebase: личные диалоги, группы,
каналы, истории, стикеры, опросы и голосовые сообщения.

## Стек

- **Next.js 15** (App Router, статический экспорт в `out/`)
- **React 19** + **TypeScript**
- **Tailwind CSS 3** + shadcn/ui + **Material 3** дизайн-токены
- **Firebase** (Auth + Firestore)
- **Capacitor** (Android-сборка)

## Запуск

```bash
npm install
npm run dev      # http://localhost:9002
```

Полезные скрипты:

```bash
npm run dev        # dev-сервер
npm run typecheck  # проверка типов
npm run build      # production-сборка (static export)
npm run cap:sync   # синхронизация Capacitor
```

## Структура

```
src/app            маршруты (/, /login, /admin, /agc/[slug])
src/components     UI: чаты, истории, настройки, shadcn/ui
src/components/ui  примитивы shadcn/ui
src/lib/brand.ts   единый источник брендинга (название, версия, слоган)
src/lib/i18n.ts    локализации (ru/en)
```

## Брендинг и тема

Все названия, версия и слоган вынесены в [`src/lib/brand.ts`](src/lib/brand.ts) —
меняйте их там, а не по файлам. Палитра и типографика Material 3 живут в
[`src/app/globals.css`](src/app/globals.css) (роли `surface-*`, `primary-container`,
`secondary-container`, `outline-variant` и т. д.) и подключены к Tailwind в
[`tailwind.config.ts`](tailwind.config.ts).

Тема запоминается в `localStorage` (`theme`), язык — в `localStorage` (`lang`).

## Служебные уведомления

- **Служебный бот «SLink»** — закреплённый чат в сайдбаре (`src/lib/service-bot.ts`):
  приветствие, уведомления об изменении профиля/аватара, о созданных группах и каналах.
  Чат создаётся лениво при первом открытии (`chats/service_<uid>`), отвечать в нём нельзя.
- **Системные сообщения внутри чатов** (`src/lib/system-notifications.ts`):
  «диалог создан», «группа создана», «канал создан», «вы покинули чат»,
  «пользователь присоединился к общему чату». Рендерятся по центру ленты
  (`components/chat/system-message.tsx`), не являются сообщениями пользователя.

## Голосовые сообщения

Запись: тап по микрофону → таймер и кнопки «отменить»/«отправить».
Ограничения: 90 секунд и ~900 КБ base64 (лимит документа Firestore — 1 МБ).
Формат выбирается автоматически (`audio/webm;codecs=opus`, fallback `audio/mp4` для Safari).
Плеер (`VoiceMessage`) — play/pause, «волна» с прогрессом и длительностью.

### Troubleshooting: `auth/invalid-api-key` при сборке

Симптом: `Error occurred prerendering page "/_not-found" ... Firebase: Error (auth/invalid-api-key)`.

Причины и что сделано:

1. GitHub Actions подставляет **пустую строку**, если секрет не создан, а `??` пустую строку не отбрасывает.
   Теперь `src/firebase/config.ts` использует trim-фолбэк: пустая переменная = «не задано» → берутся значения по умолчанию.
2. Firebase инициализировался во время статического пререндера (Next рендерит клиентские компоненты и на сервере).
   Теперь `initializeFirebase()` возвращает `null` на сервере и не бросает исключение — сборка не зависит от ключей.
3. `React.useMemo`-запросы Firestore (`/admin`) больше не вызывают `collection(db!)` при `db === null`.

Проверено локально: `npm run build` проходит и с пустыми env-переменными, и с заведомо неверным ключом.

## Сборка APK (GitHub Actions)

Готовый исправленный воркфлоу лежит в [`docs/ci/build.yml`](docs/ci/build.yml) — скопируйте его в
`.github/workflows/build.yml` (файла `main.yml` в репозитории нет). Автоматически заменить
воркфлоу агент не может: у GitHub App нет права `workflows`.

Запускается на push в **любую** ветку, на PR в `main` и вручную (`Run workflow`) — раньше триггер был только `push → main`,
поэтому сборки с рабочих веток (например `cline/*`) вообще не стартовали.

Что важно для успешной сборки:

- **JDK 17**, а не 21: Capacitor 6 использует AGP 8.2/Gradle 8.2, которые с JDK 21 падают.
- Детерминированная установка зависимостей — `npm ci`.
- `npx cap add android`, если платформа отсутствует/неполная, затем `npx cap sync android`.
- Готовый файл — артефакт **`slink-debug-apk`** (`android/app/build/outputs/apk/debug/app-debug.apk`).

Секреты репозитория (Settings → Secrets and variables → Actions), опционально:
`FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_PROJECT_ID`, `FIREBASE_STORAGE_BUCKET`,
`FIREBASE_MESSAGING_SENDER_ID`, `FIREBASE_APP_ID`. Если их нет — используются значения по умолчанию из
`src/firebase/config.ts`.

## Микрофон в Android APK

Голосовые сообщения используют `getUserMedia` + `MediaRecorder` внутри WebView. Чтобы Android
разрешил запись, в **итоговом** манифесте должны быть `RECORD_AUDIO` и `MODIFY_AUDIO_SETTINGS`:

- [`plugins/slink-native`](plugins/slink-native) — локальный Android-плагин, чей манифест Gradle
  вливает в манифест приложения при сборке. Он подключается автоматически при `npx cap sync`,
  поэтому **менять CI-воркфлоу не нужно**: в `capacitor.settings.gradle` появляется
  `include ':slink-native'`.
- Runtime-разрешение запрашивает сам мост Capacitor
  (`BridgeWebChromeClient.onPermissionRequest` → `RECORD_AUDIO`) в момент вызова `getUserMedia`.
- `npm run android:permissions` (`scripts/patch-android-permissions.mjs`) — страховка для
  локальных сборок: правит `android/app/src/main/AndroidManifest.xml`, если плагин не подключён.
- В `docs/ci/build.yml` добавлен шаг проверки: билд падает, если `RECORD_AUDIO` нет в
  merged-манифесте.

## Настройки

Вкладки: **Профиль**, **Оформление**, **Данные**, **Язык**.

- Оформление: тёмная тема, анимации, компактный список чатов, показ историй, Enter-отправка.
  Всё хранится в `localStorage` (`slink:settings`) и применяется до первой отрисовки.
- Данные: размер кэша и хранилища, **очистка кэша** (`src/lib/cache.ts`), экспорт профиля в JSON,
  сброс настроек оформления. Очистка удаляет кэш/Cache API/временные ключи, но **не трогает**
  `slink:settings`, `theme`, `lang` и сессию входа (IndexedDB Firebase не чистится).

## Анимации

Набор утилит в `globals.css`: `anim-fade-up`, `anim-pop`, `anim-slide-right`, `anim-float`,
`anim-pulse-ring`, `anim-shimmer`, `anim-gradient`, `anim-press`, задержки `anim-delay-1…5`.
Используются в списке чатов, сообщениях, пустых состояниях, логине и диалогах.
Отключаются тумблером «Анимации» (класс `animations-off` на `<html>`) и уважают системный
`prefers-reduced-motion`.

## Логотип

Используется `public/icons/SLinkBetaLogo.png` без перекраски (жёлтый бабл «SLink Beta»).
Палитра приложения при этом не менялась — по умолчанию violet.

## Палитры, тема чата и папки

- **Расцветки приложения** — «Настройки → Оформление»: violet (по умолчанию), teal, rose, amber,
  emerald, ocean. Реализация — CSS-переопределения `html[data-palette='…']` в `globals.css`,
  выбор сохраняется в профиле (`prefs.palette`) и дублируется в `localStorage` для мгновенного
  применения до загрузки профиля.
- **Оформление конкретного чата** — меню чата → «Оформление чата»: обои (точки/сетка/градиент/
  волны/свечение), цветовая тема пузырей (те же 6 палитр) и цвет имени. Хранится в
  `users/{uid}.prefs.chatSettings[chatId]`, применяется классами `chat-theme-*`, `wallpaper-*`,
  `name-color-*`.
- **Папки с чатами** — чипы под фильтрами и кнопка «Папка»: создание, редактирование состава,
  удаление. Хранится в `users/{uid}.prefs.folders`.

## Каналы: ссылки, подписка, обсуждение

- Каналы создаются с детерминированным id `chats/channel_<slug>` — без составных индексов и без
  гонок при создании. Слаг транслитерируется (кириллица → латиница).
- Ссылка: `/join/?slug=<slug>` (работает в статическом экспорте и в APK) и старый путь `/agc/<slug>`.
  На странице — описание, число подписчиков, кнопка «Подписаться» или «Открыть канал».
- Владелец в «Настройках канала» задаёт название, описание, публичность **и группу для
  комментариев** — в шапке канала появляется кнопка «Обсуждение».
- После подписки канал открывается автоматически (id передаётся через `sessionStorage`).

## Приватность, устройства и ключи

«Настройки → Приватность»: видимость времени захода, фото профиля, кто может писать,
отчёты о прочтении; список **активных сеансов** (устройство/платформа/последняя активность,
текущее устройство помечено) и **ключи доступа** (генерация `SL-XXXX-XXXX-XXXX`, копирование, отзыв).

Всё хранится в `users/{uid}.prefs`, поэтому не требует новых коллекций и правил Firestore.
Ограничение: список сеансов и ключи — клиентские (без Cloud Functions они не управляют
Firebase Auth напрямую).

## Новое в этой итерации

- **Профиль**: баннер (пресеты + загрузка 1200×400), дата рождения, музыка профиля
  (пресеты + своя mp3-ссылка, проигрывается в профиле), «был(а) в сети …»,
  круглые аватарки (квадратный контур исправлен), скрытие служебных e-mail вида `*@covechat.local`.
- **Статусы сообщений**: одна галочка — отправлено, две — доставлено, две голубые — прочитано.
  Прочтение пишется в `chats/{id}.reads[uid]` при открытии чата.
- **Реакции**: 6 эмодзи на сообщение (`reactions` в документе сообщения), тумблер по клику.
- **GIF**: меню вложений → GIF, отправляется сообщением `type: 'gif'`.
- **Аудиозвонки**: WebRTC P2P, сигнализация — сообщения `type: 'call'` (без новых коллекций).
  Нужны оба онлайн и разрешённый микрофон; TURN-сервера нет, поэтому в «сложных» NAT звонок
  может не установиться.
- **Архив**: меню чата → «В архив», чип «Архив» в сайдбаре.
- **Супергруппы**: публичная группа по ссылке `/join/?group=<slug>`, документ `chats/group_<slug>`,
  вступление по ссылке, настройки названия/описания/публичности.
- **Уведомления**: тумблер в «Оформлении» → разрешение браузера; всплывают о новых сообщениях
  в других чатах, пока приложение открыто. Для фоновых пушей нужен FCM + серверные ключи.
- **Смена пароля** в «Приватности» (reauthenticate + updatePassword).

## Медиа и «печатает»

- **Фото**: меню вложений → «Фото» (до 4 изображений, сжатие в JPEG, лимит под документ Firestore).
- **Видеокружок**: меню вложений → «Видеокружок» — фронтальная камера обрезается в квадрат через
  canvas, запись MediaRecorder (220 кбит/с, до 8 секунд), отправляется сообщением `type: 'video-note'`
  и показывается круглым видео с кнопкой звука.
- **Статус «печатает…»**: при вводе пишется `chats/{id}.typing[uid]`, отображается в шапке чата и в
  списке диалогов, гаснет через ~7 секунд; сбрасывается при отправке.
